# CME clean core (каркас)

Узкий движок для одной вертикали (товарка). Оффер — это данные (`examples/offer_example.json`),
код ничего не знает о конкретном товаре.

## Что здесь есть

| Модуль | Зачем |
|---|---|
| `offer.py` | Карточка оффера: проверенные утверждения, запрещённые, фото товара |
| `atoms.py` | Атомы Brain, JSON-схема с длиной атома, проверка утверждений кодом |
| `compiler.py` | Бюджет: сначала MAY, потом SHOULD; если MUST не влезает — остановка со списком |
| `receipt.py` | Один расчёт статуса; отдельные receipt для кадра и для видео; точный отправленный текст |
| `qa.py` | Проверки кодом (файл, якоря, OCR); судья-модель одним запросом на кадр и только как доказательство; `make_qa_checks` собирает набор для шота |
| `brain.py` | Запрос атомов по API со схемой, повтор только по упавшим, патч по ID |
| `providers.py` | Тир адаптера (free/paid) задаётся явно, free только при `allow_free`; лог вызовов; проверка модели, которая реально ответила; fallback только объявленный и только на сбой инфраструктуры |
| `registry.py`, `adapters/` | Каталог адаптеров (`adapters.json`) и настройки запуска (`settings.example.json`): Brain и судья через OpenRouter, картинки через HF Space или fal, free и paid рядом, выбор явный |
| `radar/` | Creative Radar: ручной FIND, лента с видео, shortlist, ручной AI-анализ (см. раздел ниже) |
| `smoke.py` | Первый живой тест: `python -m cme.smoke brain|frame|all`, всё помечается TEST_ONLY |
| `state.py` | Перенос кадров между запусками только для того же оффера и контракта и только если хэш файла не изменился |
| `vertical.py` | Правила вертикали из данных: гейт оффера и проверка атомов до платных вызовов |
| `run.py` | Один шот: гейты → компиляция → receipt → отправка → QA → вердикт |

## Вертикаль

`verticals/physical_goods_us.json`: обычные физические товары, гео США. Правила лежат в данных, не в коде:

- утверждения про происхождение («Made in USA», флаг), отзывы и звёзды, «#1», медицинские/авторитетные, гарантии
  допускаются только как дословно проверенное утверждение из карточки оффера;
- категории ножей: кухонные требуют аудиторию 18+ и проверку допуска рынка на платформе;
  некухонные заблокированы на Meta; для таких категорий платформа в карточке обязательна;
- гео оффера должно совпадать с гео вертикали.

**Набор стартовый и не является юридической консультацией.** Источники указаны в файле. Правила платформ и FTC
меняются, перед live-запуском их нужно сверить. У TikTok список стран, где допустимы ножи, в моей выдаче оказался
обрезан, поэтому допуск для США надо проверить отдельно.

## Инварианты (закреплены тестами)

- Нет текста движка в промпте: промпт = склейка атомов.
- Нет `unknown-contract`: без `contract_id` и `run_id` receipt не создаётся.
- Провайдеру уходит ровно тот текст, что связан с receipt; дописывать нельзя.
- PASS только если: выполнена хотя бы одна проверка кодом, нет невыполненных обязательных проверок и **каждый MUST-атом подтверждён проверкой результата** (кодом или судьёй). Наличие текста в промпте означает DELIVERED, но не VERIFIED. Если MUST проверить нечем, это SHOULD.
- Receipt кадра покрывает атомы image и qa одного шота, receipt видео покрывает атомы motion. Они не смешиваются.
- Дубликат ID отклоняет все вхождения; ошибка снимается только когда этот ID пришёл валидным в следующем раунде.
- Любая попытка оставляет запись: ошибка провайдера или QA, блокировка бюджета или гейта попадают в `attempts` и в файл receipt, затем исключение пробрасывается дальше.
- Состояние привязано к одному офферу и контракту; смешивание даёт `StateMismatch`.
- Пути к фото разрешаются при загрузке оффера в абсолютные; в запрос к Brain уходят только имена файлов.
- Удаление или понижение MUST-атома требует причины, в отчёте всегда строка «потеряно: …».
- Бесплатный адаптер допускается, если он объявлен как free в каталоге и запуск явно разрешает free (`allow_free`). Неявный free, неверно помеченный `:free`-ID и `openrouter/free` отклоняются.
- Если ответила не та модель, которую просили, вызов отклоняется и логируется.
- В коде движка нет слов из тестового оффера и слов вертикали (ножи, платформы, «Made in USA»): всё это в данных.
- Гейты вертикали срабатывают до любого платного вызова.

## Creative Radar (FIND + ручной просмотр)

Локальный интерфейс для поиска и ручного отбора рекламы физических товаров (вертикаль `Physical Products` зафиксирована).
Ничего не запускается само: поиск, анализ и каждое решение это явное действие оператора.

    pip install -r requirements.txt            # нужен requests; для анализа ролика также ffmpeg и ffprobe в PATH
    export SOCIALCRAWL_API_KEY=...             # платный поиск (старый движок); без ключа состояние NOT_CONFIGURED
    export OPENROUTER_API_KEY=...              # только для кнопки «Анализировать»
    cp settings.example.json settings.json     # там analyst_adapter (бесплатная модель по умолчанию)
    python -m cme.radar --data radar_data --open
    # или сначала импортировать сохранённый файл старого CME:
    python -m cme.radar --data radar_data --import /путь/к/tiktok_discovery.json

Откроется `http://127.0.0.1:8765/`. Стрелки вверх/вниз (или влево/вправо) переключают объявления, пробел ставит видео на паузу.
Кнопки: **Анализировать** (один запрос к модели по кадрам ролика), **В shortlist** и **Исключить** (причина обязательна),
**Пропустить**, **Открыть оригинал**. Вкладки: Лента, Shortlist, Пропущенные, Исключённые. Всё хранится в
`radar_data/radar.db` (SQLite) и переживает перезапуск; решения оператора лежат отдельно от данных объявления.

### Рабочая передача FIND → анализ → атомы → изображение

Для производства укажи реальную карточку целевого товара (с настоящим фото товара), ключи OpenRouter и Hugging Face,
и запусти Radar, например:

    python -m cme.radar --data radar_data --settings settings.json --offer offers/car_vacuum.json --production-shots 1 --open

`--offer` указывает целевой товар, который должен появиться в новом креативе; `--production-shots` принимает `1..6`.
Пример `examples/offer_example.json` намеренно не годится для производства, потому что содержит одноцветную заглушку:
Radar покажет `BLOCKED` и не вызовет Brain/генератор, пока не будет передано реальное фото товара.

1. Нажми FIND и выбери объявление. Переведи его в **Shortlist**.
2. Вкладка **Shortlist** → **Анализировать**. Анализ видит только 6 выборочных кадров, поэтому механизм и переносимость остаются гипотезами.
3. После статуса `OK` нажми **Создать кадр**. Radar отдаёт сохранённый результат анализа в существующий `cme.smoke all` через `--source-contract`; Brain создаёт текущие стабильные атомы, а далее штатные compiler, delivery receipt, image provider и QA работают без обходного пути.
4. Сгенерированные изображения, `atoms.json`, `atoms_manifest.json`, `state.json`, `calls.jsonl` и receipts сохраняются в `radar_data/production/<run-id>/`. Кадры видны прямо в Radar. При `--production-shots N` они генерируются последовательно: принятый предыдущий кадр становится reference следующего; после `UNVERIFIED` или `FAILED_QA` последовательность останавливается.

В передачу попадает результат анализа и его ID, но не исходные URL и локальные пути к видео/кадрам. Хэш source-контракта связывается с manifest, а атомный контракт и receipts сохраняют существующие проверки. Кнопка требует Shortlist и успешный анализ; целевое фото проверяется до первого вызова Brain. `PASS` у кадра и статус `TEST_ONLY` не означают доказанную коммерческую эффективность или готовую прибыльную связку.

Что используется из старого CME (файлы скопированы без изменений, их хэши проверяет тест, список в `cme/radar/legacy/MANIFEST.json`):
`discover_and_rank` (сбор, фильтры, ранжирование), `score_tiktok_candidate` (оценка источника), `classify_vertical`
(релевантность источника), клиент SocialCrawl TikTok Top Ads. Не перенесены: `source_gate`, скачивание и OCR, оркестратор,
Layer 2 и 3. Адаптация одна: `radar/find.py` приводит результат к компактной записи; неизвестное остаётся неизвестным.

Две оценки намеренно разделены: **оценка источника** (старый ранжировщик по данным источника) и **оценка механизма**
(гипотеза модели по кадрам, только если анализ запускали; это не доказательство прибыльности). Общего числа нет.

Ограничения, о которых стоит знать:

- Платный поиск с реальным ключом в этой среде не выполнялся: проверено настоящим старым кодом на синтетических ответах API.
- Старый движок сам отбрасывает объявления без видео, поэтому запись без видео возможна только через импорт.
- Ссылки на видео и обложки с CDN часто подписаны и устаревают: тогда показывается «Видео недоступно», анализ вернёт
  `VIDEO_UNAVAILABLE`, а не выдуманный разбор.
- Анализ видит только извлечённые кадры (в записи сохраняются их временные метки и хэши), не весь ролик. Бесплатная модель
  по умолчанию не проверялась вживую, качество разбора неизвестно.
- Импортируется только файл `discovery` старого CME. Другие форматы отклоняются.
- `ai_developer_tools.json` лежит в данных только потому, что старый `market_taxonomy.py` строит на него алиас при импорте; Radar
  его не использует.
- Интерфейс проверен в Chromium без H.264. Воспроизведение mp4 зависит от вашего браузера.

## Первый живой тест (бесплатные модели, один кадр)

    pip install -r requirements.txt
    export OPENROUTER_API_KEY=...        # Brain и судья
    export HF_TOKEN=...                  # Space с ZeroGPU
    cp settings.example.json settings.json
    python -m cme.smoke brain --out out  # один вызов Brain, пишет atoms.json + atoms_manifest.json
    # откройте out/atoms.json и посмотрите атомы глазами
    python -m cme.smoke frame --out out  # один кадр, receipt, честный вердикт


### Старый transfer-контракт → текущие атомы (не меняя схему атомов)

Brain может получить компактный контекст из принятого JSON старого CME через `--source-contract`. Поддерживаются старые
контракты с `mechanism`, `transfer`, `rebuild_plan` и/или `image_creative_contract`, а также сохранённый JSON анализа Radar
с `mechanism_hypothesis` и `transferability`. Пример:

    python -m cme.smoke brain --offer examples/offer_example.json --settings settings.json --out out \
      --source-contract /путь/к/accepted_old_cme_contract.json \
      --brief "Create a target-native product ad; preserve the causal mechanism, not the source ad's appearance." --shots 3

Это только входной мост: он не добавляет модулей и не меняет атомную схему. В Brain передаются механизм, правила переноса,
целевая последовательность кадров и доказательства; исходные URL, локальные пути и наборы альтернативных рекламных сценариев
не передаются. Карточка текущего оффера остаётся единственным источником проверенных фактов о целевом товаре. Хэш исходного
контракта записывается в `atoms_manifest.json`. Передача контекста помогает сохранить замысел, но не доказывает, что модель
воплотит все детали: обязательные атомы всё равно должны пройти существующие compiler/receipt/QA.


### Фото товара и визуальная проверка идентичности

- При обычном запуске `frame` известная одноцветная заглушка в `examples/photos/product_01.png` блокируется до вызова генератора. Замените её настоящей фотографией целевого товара в карточке оффера. В офлайн-тестах инъецированный fake transport допускает синтетические фикстуры.
- Генератор получает предыдущий кадр (если он есть), затем фото целевого товара. Порядок и SHA-256 каждого входа записываются в receipt как `image_inputs`; абсолютные локальные пути не сохраняются.
- Judge получает сгенерированный кадр и до трёх исходных фотографий целевого товара с явно обозначенными ролями. Дополнительная обязательная проверка `cme_product_identity_ref` сопоставляет форму, конструкцию, цвет и отличительные детали товара. Если Judge не вернул доказательный ответ или референс не передан, результат остаётся `NOT_RUN`/`UNVERIFIED`, а не PASS.
- Проверка модели не является гарантией идеального визуального совпадения. Перед коммерческим использованием просматривайте кадры; свободный/неподтверждённый адаптер по-прежнему помечается `TEST_ONLY`.

Что смотреть после запуска: `out/calls.jsonl` (какая модель просили и ответила, статусы), `out/receipts/*.json`
(точный промпт, проверки, вердикт, `commercial_status`), `out/state.json` (попытки, перенос).

- Любой результат от free или неподтверждённого адаптера помечается `TEST_ONLY`. `CANDIDATE` возможен только для
  платного адаптера с `verified: true`.
- `allow_unverified: true` в `settings.example.json` нужен только для первого теста. После успешного живого вызова
  поставьте `verified: true` у проверенного адаптера в `adapters.json` и уберите флаг.
- Если free-модель отвергает `json_object`, поменяйте `response_format_mode` у `openrouter_free_brain` на `json_schema`
  или `prompt`.
- Без OCR-движка проверка «нет текста» даёт NOT_RUN и вердикт UNVERIFIED. Для теста без OCR есть `--no-ocr-required`
  (проверка остаётся в receipt как необязательная).
- Квота ZeroGPU кончилась: код возврата 2, попытка записана. Падать в платный fallback без объявления нельзя.
- `max_attempts_per_shot` защищает квоту между CLI-запусками одного и того же непустого оффера и контракта; после лимита запуск останавливается и пишет `blocked_*.json`.
- `atoms_manifest.json` привязывает хэш атомов и фотографии к офферу/контракту. Если атомы в `out/atoms.json` изменены, `frame` блокируется; `--atoms` с внешним файлом остаётся `TEST_ONLY`.
- Коды возврата `6` (`UNVERIFIED`) и `7` (`FAILED_QA` / `NOT_DELIVERED`) означают, что артефакты сохранены, но проверка не завершилась успешным `PASS`.

## Ручной live запуск через GitHub Actions

Workflow `.github/workflows/live-smoke.yml` запускается вручную через **Actions → CME live smoke → Run workflow**. Он не запускается на каждый push и не меняет обычный офлайн CI. В выборе **Use workflow from** выбери ветку `feat/legacy-transfer-product-identity-qa-2026-10-22` или ту ветку, в которой находятся эти изменения.

### Перед первым запуском

1. В **Settings → Secrets and variables → Actions** создай два repository secrets: `OPENROUTER_API_KEY` и `HF_TOKEN`. Ключи не вставляй в поля запуска или файлы.
2. Настоящее фото товара должно быть доступно в выбранной ветке по пути внутри репозитория, например `offers/car-vacuum/front.jpg`. Путь указывается относительно корня репозитория и прописывается в `photos` в OfferCard JSON. Текущий репозиторий публичный: закоммиченное фото будет публичным.
3. В поле `offer_json` вставь JSON карточки своего целевого товара (`offer_id`, `name`, `product_type`, непустой `verified_claims`, `photos`; при необходимости `forbidden_claims`, `platform`, `geo`, `product_category`, `confirmations`). Не используй `examples/offer_example.json`: его фото — заглушка, которая блокирует запуск.
4. В поле `source_contract_json` вставь JSON результата анализа рекламы из локального Creative Radar — объект `analyses[].result` с полями вроде `mechanism_hypothesis` / `transferability` — либо принятый старый CME transfer contract с `mechanism`, `transfer`, `rebuild_plan` или `image_creative_contract`. В локальном Radar открыть `http://127.0.0.1:8765/api/candidate?id=ID_ОБЪЯВЛЕНИЯ` и взять результат нужного анализа. Для старого контракта проверка `source_review.source_verification`, если она обязательная, всё так же должна иметь `status=PASS`.

В workflow доступны три режима:

- **`brain`** — проверяет OfferCard, настоящее фото и source contract до обращения к модели, затем создаёт `atoms.json` и `atoms_manifest.json`. Артефакт: `cme-brain-out`. Просмотри атомы перед генерацией.
- **`frame`** — генерирует один кадр из успешного Brain-артефакта. Введи его числовой **Workflow run ID** в `brain_run_id`. Для повторной попытки укажи `previous_frame_run_id`; workflow восстановит state и лимит попыток. Запуск разрешён только с той же ветки и того же commit SHA, что и Brain.
- **`all`** — полный путь за один запуск: source contract → Brain → атомы → выбранное число последовательных кадров → QA. `shots` принимает 1–6, по умолчанию 1. Нужны оба ключа. Используй этот режим, когда хочешь запустить весь процесс без отдельного шага `frame`.

Перед генерацией workflow проверяет JSON, наличие и качество фото, совместимость manifest с оффером и происхождение артефактов. Ошибка на этом этапе не расходует квоту провайдеров. Сырой `source_contract.json` удаляется перед загрузкой артефакта; в manifest остаётся его хэш. Выход, кадры, квитанции, состояние и журнал вызовов хранятся в артефакте 7 дней.

`no_ocr_required` по умолчанию выключен. Если его включить, отсутствие OCR не будет обязательным блокирующим условием, но все проверки и их статусы останутся в receipts. Код возврата CME `6` означает `UNVERIFIED`, `7` — провал QA/доставки; GitHub job будет красным, а артефакты сохранятся. Адаптеры в текущей конфигурации бесплатные и не подтверждены для коммерческого использования, поэтому успешный результат остаётся `TEST_ONLY`: проверь изображения и receipts вручную.
## Выбор адаптера для тестов

`adapters.json` содержит бесплатный `hf_zerogpu_flux2_klein` и платные `fal_flux2_pro`, `fal_seedream`.
`settings.example.json` выбирает, какой запускать, и нужен ли `allow_free`. Платный fallback при исчерпании квоты ZeroGPU
нужно объявить явно (`fallback_adapter`), иначе исчерпание квоты остановит запуск.

В каталоге у адаптеров стоит `verified: false` и значения `CONFIRM_ME`: `api_name` и порядок аргументов Space, `model_path`
и имя параметра референса у fal нужно подтвердить на страницах API до первого живого запуска. Пока `CONFIRM_ME` на месте,
адаптер отказывается собираться, а не делает вызов вслепую.

## Запуск тестов

    pip install -r requirements.txt
    python -m unittest discover -s tests -t . -v

## Чего здесь НЕТ (честно)

- Живых вызовов: Brain и судья (OpenRouter), HF Space и fal написаны и покрыты тестами на подставных транспортах и
  клиентах, но с реальными сервисами не запускались. Порядок аргументов Space взят из диагностики вашего прошлого запуска.
- Видео и лимита расходов (платных вызовов пока нет, лимит имеет смысл добавлять вместе с первым платным адаптером).
- Стадии видео (Layer 3) и сборки ролика.
- Вырезки реального фото товара и композиции его в кадр.
- Движка OCR (проверка «нет текста» без него честно возвращает NOT_RUN, а значит PASS не выдаётся).
- Переноса модулей поиска, механизмов и переноса из старого репозитория.
- Порогов QA: значения в проверках якорей — заглушки, их нужно калибровать на реальных кадрах.
- Гарантии против утверждения о товаре внутри «обычного» атома: код ловит только kind=claim, регулируемые паттерны
  вертикали и запрещённые фразы. Остальное закрывают судья и ручной просмотр первых запусков.
- Тесты проверяют каркас на поддельных провайдерах, живые провайдеры не вызывались.
